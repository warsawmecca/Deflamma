# Deflamma · 전국 EMA·정적분 통합판

2026-11-14. 한국 육지의 B07 픽셀을 150초마다 계산한다. 평년 모델은 함께 제공하며 실시간 날씨 API는 사용하지 않는다. 기존 지도, 행·열 커서, 전체/후보 정렬, 과거 검색, 관심 지점 기능을 유지한다.

## 실행

Python 3.10 이상. Ubuntu 예시:

```bash
cd himawari_rise_monitor
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python monitor.py --score-mode contrast --serve --output monitor_integral_output
```

브라우저: http://localhost:8765/latest_heatmap.html
Windows는 `.venv/Scripts/python.exe`를 사용한다. 기존 계산과 다른 판정 형식이므로 **새 출력 폴더**를 사용한다. 과거 출력 폴더 전체를 새 폴더에 복사하지 않는다. 저장 지점만 옮기려면 프로그램을 정지한 상태에서 기존 `watchpoints.sqlite3`를 새 출력 폴더로 복사한다. 새 형식으로 필요한 열을 자동 추가하며 지점32개·이력24시간 제한은 유지한다.

최초 실행은 **기준 관측 시각을 고정하고 그 직전2시간(48시점)의 점수를 일괄 준비**한다. 실시간으로2시간이 쌓이기를 기다리지 않는다. 원본51개(점수48개와 경계/현재 자료)를 최대4개씩 병렬로 취득한 뒤, 전국 기본점수·순위를 각 시점 한 번만 계산하고 과거→현재 순서로 EMA·정적분을 누적한다. 과거동일시각 참조도 필요하므로 첫 실행에는 다운로드·계산 시간이 필요하다.

진행 상황은 웹 상태 표시와 `bootstrap_status.json`, `monitor.log`에서 확인한다. 과거 준비가 완료된 상태만 원자적으로 확정한다. 중간 종료 시 임시 상태를 정상 상태로 사용하지 않으며, 다음 시작에 다시 준비한다. 유효한 기존 계산 상태가 있으면 직전 상태에서 이어서 실행한다. 장시간 중단·시간 간격 누락 때는 고정된 최신 기준의 직전2시간으로 다시 준비한다. 실제 공급자 결측은 채우지 않고 해당 구간을 표시한다. 관측된 상향 교차가 없으면 면적 판정을 보류한다.

## 현재 최종 후보 조건

아래 조건을 **모두** 만족해야 한다.

1. 현재 B07 밝기온도 T ≥ 저장된 해당 위치·날짜·시각의 평년 지표온도.
2. g = 0.8 × 상승 합 EMA − 하락 합 EMA > 0.
3. 관측된 최근 상향 교차부터 g의 누적 면적 > **10점·분**.
4. (최종 점수 ≥5 **그리고** 직전150초 온도 상승 ≥0.6K) **또는** 최종 점수 ≥40.

현재 조건을 통과하지 못한 점수도 EMA·적분 계산에서 삭제하거나 0으로 덮지 않는다. 280K/300K 후보 하한과 옛 노이즈 분류는 폐기했다. 점수식 안의 D에 쓰이는 300K는 부드러운 온도 가중의 중심이며 후보 하한이 아니다.

기본점수 = 100 A^0.1 B^0.4 C^0.4 D^0.1. A=온도 분위, B=b+/(b++5K), C=c+/(c++5K), D=sigmoid((T−300K)/10K). b=육지 이웃8개의 중앙값 대비, c=b−지난7일 동일시각 유효 b의 중앙값. 과거 참조는 각 과거 날짜의 평년−5K **초과** 자료가 최소4일 필요하다. 기존 순위 가산·군집 감점은 유지한다.

상승·하락 합은 (t−20분,t]의 점수 변화로 구한다. 구획을 나가는 상승과 바로 다음의 동일 크기 하락은 기존 규칙대로 대응 제거한다. EMA span=8, α=2/9. 교차는 선형 보간, 적분은 사다리꼴이며 g≤0 또는 실제 결측이면 초기화한다. 양수 상태로 기록이 시작됐으나 교차가 확인되지 않았으면 면적을 추정하지 않는다. 해독 가능한 운영 품질 플래그 자료는 현재·과거 모두 사용한다. 구조 오류와 실제 결측·손상 픽셀은 제외한다.

B07 밝기온도와 평년 지표온도는 서로 다른 물리량이다. 제공된 평년은1991–2020 NCEP/NCAR 지표온도 평년의 육지 보간값이다. 요청한 부등식을 그대로 사용하며, 이 점수는 산불 확률이나 확정 판정이 아니다.

## 용량 및 자동 삭제

기본값은 전체 JSON/지도를 매 관측마다 보존하지 않고 최신 파일만 교체한다. 전국 숫자 이력은 float32 압축 배열, 계산을 이어갈 점수·EMA·적분 상태는 float64로 저장한다. 계산용 float64를 그래프용 float32로 대체하지 않는다. 9개 사례 중 면적10.00071처럼 문턱에 가까운 시점도 원래 계산 정밀도를 유지한다.

| 항목 | 시간·개수 제한 | 항목 용량 상한 |
|---|---|---:|
| 원본 HSD 캐시 | 접근 후15분, 최대16개 | 32MiB |
| 과거 참조 T/b 벡터 | 작성 후8일, 최대4096개 | 512MiB |
| 전국 상세 숫자 이력 | 작성 후24시간, 최대576시점 | 384MiB |
| 선택적 전체 스냅샷 | 24시간, 최대32시점 | 128MiB |
| 과거 검색 결과 | 24시간, 최대32건 | 256MiB |
| 관심 지점 | 최대32곳, 각24시간·576시점 | SQLite 사용 공간 회수 |
| 처리/누락 기록 | 24시간 | SQLite 사용 공간 회수 |
| 프로그램 로그 | 5MB×4파일 | 20MB |
| 임시 쓰기·부분 다운로드 | 1시간 경과 시 제거 | 정리 대상 |

시간·개수·용량 중 어느 하나에 먼저 도달하면 오래된 항목부터 지운다. 따라서24시간과32건은 최대 보존량이며 용량이 먼저 차면 더 일찍 삭제된다. 과거 참조가 지워져도 필요할 때 공급자에서 다시 가져온다. 현재 참조는 압축 T/b만 남기므로 원본 7일치를 보관하지 않는다. 완료·실패한 과거 검색의 임시 원본/참조 캐시도 제거한다.

**전체 출력 폴더 예산은2GiB이며 새 처리 전128MiB, 과거 조회 시작 전256MiB의 여유를 검사한다.** 보호해야 할 상태를 삭제하지 않고 새 취득/저장을 보류한다. `retention_status.json`에 정리 시각·사용량·예산 상태를 기록한다. 외부 프로그램이 쓰는 파일, 운영체제·패키지·가상환경은 이 예산에 포함되지 않는다. 동시 쓰기의 일시적인 임시 공간은 별도로 필요하므로 디스크에는3~5GB 여유를 둔다.2GiB는 파일시스템 강제 할당량이 아닌 프로그램의 저장 예산이다.

매 관측 처리 전후, 매 폴링의 finally(자료 지연·수집 오류 시에도), 프로그램 시작 때 자동 정리한다. 정리는 쓰기 잠금으로 계산/결과 저장과 겹치지 않는다. 실제 삭제 실패를 성공으로 숨기지 않으며 오류를 기록한다. 코드·설정·평년 모델은 출력 폴더 밖에 두므로 정리 대상이 아니다. 심볼릭 링크를 따라 외부 파일을 지우지 않는다.

## Oracle/Ubuntu 서버에 반영

가상환경 설치 후 아래 한 번으로 수집 서비스와 독립 정리 타이머를 함께 설치한다.

```bash
sudo bash deploy/install_service.sh
systemctl status himawari.service deflamma-cleanup.timer
systemctl list-timers deflamma-cleanup.timer
journalctl -u himawari -n 60 --no-pager
```

설치 스크립트는 기존 himawari 서비스와 덮어쓰기 설정을 날짜별 백업한 뒤 새 단일 ExecStart 서비스로 교체한다. 기존 서비스는 정지·재시작된다. 기본 경로는 이 프로젝트의 `monitor_integral_output`, 포트8765이며 기존 nginx는 유지한다. 환경변수의 공개 주소는 deflamma.duckdns.org다. 다른 도메인이면 설치 스크립트의 환경변수를 변경한다. SSH/비밀키·인증서·자격증명은 포함하지 않았다.

독립 타이머는 부팅2분 후와 이후15분마다 정리하므로 수집 서비스가 중지돼도 삭제한다. 쓰기 중이라 잠겨 있으면 이번 정리를 건너뛰고 다음 실행에 재시도한다. 서버 전원이 꺼졌거나 쓰기 권한/디스크 오류가 있으면 실행 자체가 불가능하므로 무조건적인 삭제 보장은 할 수 없다. 정상 권한과 실행 가능한 서버에서 자동 삭제가 작동하도록 구현하고 테스트했다. 타이머 실패는 아래로 확인한다.

```bash
journalctl -u deflamma-cleanup.service -n 30 --no-pager
.venv/bin/python retention.py --output monitor_integral_output
```

Windows 또는 systemd 없는 실행에서도 수집 프로그램 내부 정리는 작동한다. 수집 프로그램을 종료한 동안에도 삭제하려면 위 정리 명령을 운영체제의 작업 스케줄러에 등록해야 한다.

## 조회와 검증

관심 지점 그래프는 최종 점수·원래 온도·온도 변화·주변/과거 대비·상승/하락 EMA·EMA 차이·누적 면적을 표시한다. 보존된 전국 숫자 이력은 `series/`의 압축 배열이다. 과거 조회는 별도 상태에서 요청 전 약2시간을 준비하므로 실시간 EMA 상태를 변경하지 않는다. 검색 결과 파일은 자동 보존 한도 안에서 제공한다.

```bash
.venv/bin/python -m unittest discover -s tests_release -v
.venv/bin/python monitor.py --help
```

`TEST_RESULTS.txt`와 `VERIFICATION.md`에 검증 범위를 기록했다. ZIP에는 관측 원본·옛 결과·패키지/가상환경을 포함하지 않는다. 현재 설치 ZIP의 코드를 통합한 것이며 서버 배포는 별도다.
